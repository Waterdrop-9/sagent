## 目标

验证「前期静态分析尽量扩大搜索范围（全组危险 sink 枚举，宁滥勿缺），后期 agent 判断再降误报」的两阶段提示词策略：

- prompts/common/attack-surface.md 重写为两阶段：第一阶段全组（root + 依赖库）危险 sink 枚举；第二阶段按 CWE 判定规则收紧。
- 6 个 CWE 模板「起点」节去 vh 化（clues/notes/binary/decompile 线索文件引用一律改指 Sagent 工具）。

## 结论

1. 两阶段策略生效：一阶段把 libauth/liblog 侧的命令注入链、硬编码凭据、sink 覆盖缺口全部纳入 unresolved（宁滥勿缺），二阶段只把有工具证据的链 A 确认、对 main mkdir 给出具体反证（降 FP）。
2. 链 A confirmed + PoC 不回退（与 20261014_01 的 run-3c27fd0aa510 一致）。
3. 依赖库侧候选因无 evidenceID 无法 confirmed——后续「Ghidra 加载依赖库」项可把链 B、CWE-121（liblog strcpy）升级为可确认。
4. provider 超时（deepseek-flash `Timed out waiting for response data`）是当前真实运行的主要不稳定源：两轮实验 5 次真实运行中 2 次因此失败（bash-321、bash-405），重试后均成功。报告级重试只覆盖"JSON 无效"，不覆盖"会话无输出退出"——后续可在 OpenCodeRuntime 对 exit 1 且无 report 的场景加重试。

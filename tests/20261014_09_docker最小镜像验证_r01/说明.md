# Docker 最小镜像验证（sagent:minimal）

## 目的

验证离线交付镜像 `sagent:minimal` 在本机 Docker Desktop（Apple Silicon，amd64 模拟）下
能完整跑通 sagent 流水线，并确认删减 + 扁平化没有破坏任何运行时能力。

## 背景

用户要求「只关于 sagent 的镜像、去掉 vh 与无关内容、仅 docker 即可在宿主机离线部署」。
纯净基座路线（`docker/Dockerfile`，`FROM ubuntu:24.04`）在本机不可行：构建出口仅
~44 kB/s，`security.ubuntu.com` 的 openjdk 包反复 `502 Bad Gateway`（换阿里 HTTP 源后
容器仍异常退出）。故改走**删减 + 扁平化**（`docker/slim.sh`）：

1. 从 vh 系 `sagent:r1` 启动维护容器（必须 `--entrypoint bash`，否则 `sleep infinity`
   会被镜像自带 ENTRYPOINT 当成 agent 参数，exit 2）；
2. 删除与运行无关内容（pwndbg 853M、Ghidra 11.3.1 693M、LLVM-16/18 1.2G、
   交叉编译器、npm 缓存 398M、文档/GPU/虚拟化组件等，约 2.8G）；
3. 自检（opencode / angr / ghidra-mcp / Ghidra / jar / src 全部可用）；
4. `docker export` → `docker import --platform linux/amd64` 扁平化成单层，
   `--change` 逐条恢复 ENV/ENTRYPOINT/WORKDIR/VOLUME/EXPOSE。

两个关键坑：分层镜像里 `rm` **不减小** `docker save` 体积（被删文件仍在底层），
必须扁平化；`docker import` 不带 `--platform` 会被标成宿主架构（arm64），
之后按 amd64 运行报「找不到镜像」。

## 结果

体积：

| 产物 | 体积 |
| --- | --- |
| `sagent:r1`（分层） | 10.7G |
| `sagent:minimal`（扁平化单层） | 6.27G |
| `sagent-minimal.tar.gz`（离线交付件） | 2.2G |

容器内端到端实跑（挂载宿主机 `/work`，用宿主机 `config.toml` 连 DeepSeek API）：

```bash
docker run --rm --platform linux/amd64 -v "$PWD:/work" sagent:minimal \
  --config /work/config.toml \
  --target data/01_simple_demo/server --dependency-root data/01_simple_demo \
  --goal "检查是否存在外部输入到命令执行的路径" \
  --cwe CWE-78 --poc --confirmation recall \
  --output /work/tests/20261014_09_docker最小镜像验证_r01/产物
```

`run-11113690007d`：

- confirmed 2：`0x401380`、`0x1010b0`（各 8/9 条证据，reference-chain，high）
- rejected 1：`0x401280`
- unresolved 5；PoC 生成 4 文件（两个 finding 的 `.md` + `.py`）
- 耗时 159.2s、cost $0.0437、tokens_in 183391 / out 8156 / cache_read 868736

与 vh 系 `sagent:r1` 的同目标运行（`tests/20261014_07_docker部署验证_r01/`）质量一致：
两处 confirmed 攻击链 + 一处正确 rejected + PoC 交付物，阶段 M/J、Ghidra 三会话
（root + libauth + liblog）与 paths 会话均在容器内正常工作。

## 结论

- 离线交付路线成立：部署机只需 `docker load` + `docker run`，不需要联网构建。
- 镜像内容只剩运行时：Ghidra 12.0.4 ~850M、angr ~1.1G、opencode(node 包) 821M、
  node 225M、JRE 与系统库；无法再压缩的部分若去掉会损失能力（如 angr → 失去 paths 后端）。
- 纯净基座路线保留为「构建机网络良好时的理想路线」，其两个必要修正已记入
  `docker/Dockerfile` 注释：node 26 需 `libatomic1`；npm 全局 bin 不在 PATH，需补
  `/usr/local/bin/opencode` 软链。

# CWE-606 Sagent 分析规则

本文件合并该 CWE 的攻击面、候选模型、传播/生命周期复核、误报排除和输出约束。重点：循环/递归终止条件、外部计数、上界校验、限流和资源耗尽。

# 18 搜查未校验输入控制循环条件

本轮目标：**识别循环条件或循环边界由未经校验的网络输入直接控制，导致越界处理、长时间占用或资源耗尽**。

## 起点

本仓库不产出 `clues/`、`notes/`、`binary/`、`decompile/` 目录——vh 风格章节提到的线索文件一律不存在，忽略它们，改用「Sagent 工具与证据规则」的 GhidraMCP/query_sink_paths/ELF 解析工具自行收集。优先级从高到低：

1. **GhidraMCP 导入表/函数/反编译** — 找 `recv/read/fgets/scanf/fread` 的调用点与**回边跳转（循环）**，看循环条件变量是否来自这些输入的返回值/长度字段（最精准）
2. **query_sink_paths** — 对循环内使用的索引/长度参数查数据依赖（覆盖清单，保证不漏）
3. **网络入口与 dispatch 表** — 反编译 handler 与 opcode 分发表（用于追可达性）
4. **依赖库 ELF 解析**（bash：`nm -D`/`objdump -d`/`strings`）— 未加载库的循环处理点（无 evidenceID，记 unresolved）
5. **自主探索**：递归调用深度、`while(recv(...)>0)` 累积循环、长度字段作为 for 边界

## 搜查清单

对阶段 M 候选链摘要里的每一条链，以及工具枚举出的全部输入消费点（recv/read/fgets 等）所在的循环，**必须每个都给出明确结论**。候选链摘要中没有覆盖的循环也要主动枚举，不得遗漏。

## 步骤

1. **逐链判定**：按 per-chain-judgment.md 的协议，对候选链摘要中每一条链给出 confirmed / rejected / unresolved 的明确 verdict；机械来源（callgraph/import_table/plt_link）不是确认依据，每一跳仍需要反汇编调用点证据。
2. **sink 枚举兜底**：找全网络输入消费点及其所在循环（回边跳转目标），对照候选链清单，未出现的单独判定。
3. **循环条件来源分类**：
   - 条件直接来自网络长度字段（`count = *(uint32*)buf`）→ 高危，看第 4 步
   - 条件来自 recv 返回值（`while ((n=recv(...))>0)`）→ 属于流式读取，**不是本 CWE**（除非累积量无上界进入分配）
   - 条件为常量/feof/EOF → 安全
4. **上界校验检查**：循环边界变量在进入循环前是否有常量比较拒绝（`cmp/jbe` 分支）——有且覆盖全路径 → 校验有效；无 → 未校验。
5. **影响判定**：未校验的循环边界是否用作数组索引/长度（→越界，本 CWE）或仅控制迭代次数（→资源占用；若造成每连接 fork/popen/线程创建的资源耗尽，属 CWE-400/404，**不报 confirmed，记 unresolved 注明类别**）。
6. **追调用链到网络输入**：循环边界沿调用链向上追 caller，直到追到网络入口（recv 等），或明确不在网络链路上。
7. **驳斥清单（仅 confirmed 候选必须逐项通过）**：见 per-chain-judgment.md 的 R1 source 可控性 / R2 逐跳传播 / R3 清洗约束 / R4 构造与影响。每项最多一次补充查询。

## 判定规则

- ✅ **confirmed**：循环边界直接来自未校验网络输入 + 边界用作索引/长度（造成越界）或累积分配 + 网络可达 + 驳斥清单 R1-R4 全部通过，且符合 confirmation-policy.md 的确认标准（引用链级证据时 confirmationBasis=reference-chain）。
- ❌ **rejected**：循环条件为常量/recv 返回值（流式）/有覆盖全路径的常量上界检查。反证写进 finding 的 limitations。
- ❓ **unresolved**：资源耗尽类（每连接线程/fd/popen 无上限，属 CWE-400/404）、跨组件循环未覆盖时，写 unresolved，说明缺哪一类证据，保留 evidenceIDs。

## 产出约束

最终 JSON 是唯一产出（见「Sagent 最终输出规则」）。不创建 vulns/notes/clues 目录文件。

## 硬性前置要求（所有漏洞类型通用）

### 1. 网络可达性是必要条件

本系统**只收录能通过网络请求触发的漏洞**。对每个候选漏洞，必须从网络入口（recv/read 等输入源）出发，逐跳证明可达。

- 如果路径追不回网络入口（例如只在本地启动时调用一次）→ 记为 rejected，limitations 写"本地可达但非网络可达"
- 如果前置需要认证但认证本身无漏洞 → 仍算网络可达，但严重度降级，并在 limitations 中明确"需认证"

### 2. 去重：同一漏洞不写两份报告

**"同一漏洞"判定标准**：**sink 调用点地址相同**，哪怕从不同入口/不同上游函数到达。

- 发现"另一条调用链也能到达同一 sink"：**不创建新 finding**，而是在已有 finding 的 limitations/调用链描述里追加一条入口路径
- 判定前先核对已写出的 finding 列表，确认 sink 地址是否已被记录

**例外**：同一函数但不同 sink 点算两个漏洞，各写一份。

### 3. 反作弊声明

- 普通 accept 服务器主循环（等待新连接）**不是**漏洞
- `while ((n = recv(...)) > 0)` 流式读取**不是**本 CWE
- 循环边界有常量上界检查的**不是**漏洞
- 资源耗尽类（CWE-400/404）**不报 confirmed**，记 unresolved 注明类别
- 每个输入消费循环 **必须**在产出中被引用（有漏洞或在 unresolved 中说明未分析原因）
- "rejected" 结论必须给出具体理由（条件来源/上界检查地址），不能只说"无漏洞"

## Sagent 工具与证据规则

1. 先使用 ELF 分析组中的 binaryID 和依赖关系确定范围，再使用 GhidraMCP 查询程序信息、导入、函数、字符串、反编译、调用关系和交叉引用。
2. 对高价值 sink 调用 `query_sink_paths`（循环边界/索引参数）；工具返回的 `path_found` 只是参数定义或依赖链，不能单独证明完整漏洞。
3. 每个结论必须引用 binaryID、functionID、调用点/地址和 evidenceIDs。Agent 推断必须标记为语义判断，不能把函数名或调用关系当作事实。
4. 从网络、IPC、命令行、环境、配置或文件入口逐跳检查可达性；认证要求、跨库边界、间接调用、别名和反编译限制都要记录。
5. 复核同一 sink 调用点的去重情况，不能因为多条入口路径重复创建同一个 finding。

## Sagent 最终输出规则

最终 JSON 必须包含 `findings`、`unresolved`、`coverage`。`findings[].status` 只能是 `confirmed` 或 `rejected`：

- `confirmed`：类型语义、外部可达性、传播/生命周期关系和安全影响均有工具证据；
- `rejected`：有明确反证，例如常量、路径不可达、有效校验、互斥控制流或对象实例不同。

证据不足、工具不支持、查询失败、跨组件未覆盖或只能提出候选时，不得放入 findings，改写入 `unresolved`，保留原因和 evidenceIDs。不要生成或执行 PoC；PoC 由独立阶段接收 confirmed findings。

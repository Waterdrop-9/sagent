# CWE-134 Sagent 分析规则

本文件合并该 CWE 的攻击面、候选模型、传播/生命周期复核、误报排除和输出约束。重点：格式参数与普通变参实参的区别、变参调用和格式化 wrapper。

# 11 搜查格式化字符串漏洞

本轮目标：**识别 printf 系列函数第一个参数（格式串）由网络输入可控导致的格式化字符串漏洞**。

## 起点

本仓库不产出 `clues/`、`notes/`、`binary/`、`decompile/` 目录——vh 风格章节提到的线索文件一律不存在，忽略它们，改用「Sagent 工具与证据规则」的 GhidraMCP/query_sink_paths/ELF 解析工具自行收集。优先级从高到低：

1. **GhidraMCP 导入表/函数/反编译** — 找 `printf/fprintf/sprintf/snprintf/syslog/vprintf/vfprintf/dprintf/asprintf` 及自定义 wrapper（如 `log_message`/`logMsg`）的全部调用点（最精准）
2. **query_sink_paths** — 对每处调用查**参数 0（格式串）**的数据依赖（覆盖清单，保证不漏）
3. **网络入口与 dispatch 表** — 反编译 handler 与 opcode 分发表（用于追可达性）
4. **依赖库 ELF 解析**（bash：`nm -D`/`objdump -d`/`strings`）— libauth/liblog 等未加载库的 printf 族调用点与 wrapper 定义（无 evidenceID，记 unresolved）
5. **自主探索**：函数指针、宏包装的日志函数（MSG_* 宏展开）

## 搜查清单

对阶段 M 候选链摘要里的每一条链，以及工具枚举出的全部 printf 族调用点（含自定义 wrapper），**必须每个都给出明确结论**。候选链摘要中没有覆盖的调用点也要主动枚举，不得遗漏。

## 步骤

1. **逐链判定**：按 per-chain-judgment.md 的协议，对候选链摘要中每一条链给出 confirmed / rejected / unresolved 的明确 verdict；机械来源（callgraph/import_table/plt_link）不是确认依据，每一跳仍需要反汇编调用点证据。
2. **sink 枚举兜底**：用 GhidraMCP 找全 printf 族调用点（含 wrapper），对照候选链清单，未出现的单独判定。
3. **格式参数分类**：对每处调用检查**第一个参数**：
   - 字符串字面量（`"..."`）→ 常量，安全，记录 rodata 地址为反证
   - 宏（MSG_*）→ 查宏定义/反汇编确认展开后是否常量
   - 变量 → 进入下一步追源
4. **区分 wrapper 的形参位置**：自定义 wrapper（如 `log_message(fmt, ...)`）判定时必须确认**哪个形参最终成为 printf 的格式串**。若网络数据只作为 `%s` 变参**实参**传入（`log_message("%s", user)` 或 wrapper 内部格式串为常量）→ 那是日志注入/CWE-117 或其他类，**不报本 CWE**，在 unresolved 中注明类别。
5. **追调用链到网络输入**：变量格式串沿调用链向上追 caller（GhidraMCP 交叉引用），直到追到网络入口（recv 等），或明确不在网络链路上。
6. **驳斥清单（仅 confirmed 候选必须逐项通过）**：见 per-chain-judgment.md 的 R1 source 可控性 / R2 逐跳传播 / R3 清洗约束 / R4 构造与影响。每项最多一次补充查询。

## 判定规则

- ✅ **confirmed**：格式参数（参数 0）来自网络输入 + 无过滤 + 驳斥清单 R1-R4 全部通过，且符合 confirmation-policy.md 的确认标准（引用链级证据时 confirmationBasis=reference-chain）。
- ❌ **rejected**：格式串为常量字面量（引用 rodata 地址与调用点反汇编）、或网络数据只作为变参实参（`printf("%s", user)`）、或路径不可达。反证写进 finding 的 limitations。
- ❓ **unresolved**：格式串来自未分析的 wrapper 内部/跨组件函数、工具未覆盖时，写 unresolved，说明缺哪一类证据，保留 evidenceIDs。

## 产出约束

最终 JSON 是唯一产出（见「Sagent 最终输出规则」）。不创建 vulns/notes/clues 目录文件。

## 硬性前置要求（所有漏洞类型通用）

### 1. 网络可达性是必要条件

本系统**只收录能通过网络请求触发的漏洞**。对每个候选漏洞，必须从网络入口（recv/read 等输入源）出发，逐跳证明可达。

- 如果路径追不回网络入口（例如只在本地启动时调用一次）→ 记为 rejected，limitations 写"本地可达但非网络可达"
- 如果前置需要认证但认证本身无漏洞 → 仍算网络可达，但严重度降级，并在 limitations 中明确"需认证"

### 2. 去重：同一漏洞不写两份报告

**"同一漏洞"判定标准**：**sink 调用点地址相同**，哪怕从不同入口/不同上游函数到达。

- 发现"另一条调用链也能到达同一 sink"：**不创建新 finding**，而是在已有 finding 的 limitations/调用链描述里追加一条入口路径
- 判定前先核对已写出的 finding 列表，确认 sink 地址是否已被记录

**例外**：同一函数但不同 sink 点算两个漏洞，各写一份。

### 3. 反作弊声明

- `printf("constant")` 不是漏洞——不要把所有 printf 都报
- `printf("%s", user_input)` 不是格式字符串漏洞；`sprintf(buf, "%s", user)` 也不是（是潜在的缓冲区问题，归其他 CWE）
- 只有**第一个参数本身**可控才是本题漏洞
- 每个 printf 族 sink **必须**在产出中被引用（有漏洞或在 unresolved 中说明未分析原因）
- "rejected" 结论必须给出具体理由（格式串常量地址/变参实参位置），不能只说"无漏洞"

## Sagent 工具与证据规则

1. 先使用 ELF 分析组中的 binaryID 和依赖关系确定范围，再使用 GhidraMCP 查询程序信息、导入、函数、字符串、反编译、调用关系和交叉引用。
2. 对高价值 sink 调用 `query_sink_paths`（格式串=参数 0）；工具返回的 `path_found` 只是参数定义或依赖链，不能单独证明完整漏洞。
3. 每个结论必须引用 binaryID、functionID、调用点/地址和 evidenceIDs。Agent 推断必须标记为语义判断，不能把函数名或调用关系当作事实。
4. 从网络、IPC、命令行、环境、配置或文件入口逐跳检查可达性；认证要求、跨库边界、间接调用、别名和反编译限制都要记录。
5. 复核同一 sink 调用点的去重情况，不能因为多条入口路径重复创建同一个 finding。

## Sagent 最终输出规则

最终 JSON 必须包含 `findings`、`unresolved`、`coverage`。`findings[].status` 只能是 `confirmed` 或 `rejected`：

- `confirmed`：类型语义、外部可达性、传播/生命周期关系和安全影响均有工具证据；
- `rejected`：有明确反证，例如常量、路径不可达、有效校验、互斥控制流或对象实例不同。

证据不足、工具不支持、查询失败、跨组件未覆盖或只能提出候选时，不得放入 findings，改写入 `unresolved`，保留原因和 evidenceIDs。不要生成或执行 PoC；PoC 由独立阶段接收 confirmed findings。

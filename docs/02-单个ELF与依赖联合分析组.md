# 单个 ELF 与依赖联合分析组

状态：讨论稿 v0。

本文定义第一个最小分析闭环：用户提供一个 ELF，系统解析它的依赖，建立一个逻辑分析组，后续静态分析以该组为共同上下文。

本文暂不处理固件解包、目录和压缩包批量分析、交互工作区及动态执行。

## 设计结论

“单个 ELF 加相关依赖”适合作为第一阶段的基础能力。相关依赖应定义为从根 ELF 开始递归得到的依赖闭包，不是同一目录中所有看起来相关的文件。

```text
根 ELF
  → 读取直接依赖
  → 解析依赖文件
  → 递归处理依赖的依赖
  → 建立依赖闭包
  → 生成逻辑分析组
  → 联合静态分析
```

联合分析共享组件关系、符号关系和调用上下文。每个 ELF 仍保留自己的身份、来源和地址空间，不把多个文件拼成一个二进制。

## 模块职责

本模块负责：

- 接收用户指定的根 ELF
- 读取直接依赖声明
- 在受控来源中查找依赖文件
- 递归建立依赖关系
- 去重组件并保留来源
- 生成分析组
- 记录依赖处理结果、待处理原因和候选文件
- 向静态分析模块提供分析组清单

本模块不负责反编译、污点分析、CWE 判断、Agent 推理和报告生成。

## 领域对象

根 ELF 是用户指定的分析起点，也是分析组中必需的组件。

依赖声明是 ELF 或分析工具指出的组件需求，例如动态链接依赖、导入符号和符号版本。声明只说明需要什么，不代表文件已经找到。

本地依赖是已经与项目内具体文件对应的依赖。文件路径、哈希、架构和解析来源都要保留。

常见库知识引用是项目内没有对应文件，但可以依据库名使用通用库知识继续处理的依赖。它不伪造本地文件，也不进入本地依赖闭包。

待处理依赖是已经发现声明，但当前没有可用文件或通用库知识，或者候选文件无法选择的依赖。它仍然要进入分析结果。

依赖闭包是从根 ELF 开始，沿项目内已建立的依赖关系递归得到的组件集合。

联合分析组由根 ELF、依赖闭包、组件关系和必要上下文组成，是后续静态分析的默认范围。

## 分组规则

- 一个根 ELF 生成一个分析组。
- 直接依赖和递归依赖进入同一组。
- 一个依赖组件可以被多个根 ELF 的分析组引用。
- 相同内容只保留一个组件身份，不因路径不同而复制。
- 没有动态依赖的静态链接 ELF 形成单成员分析组。
- 项目内没有对应文件的依赖不会丢失根 ELF；常见库可以转为通用库知识引用，其他依赖保留为待处理关系。
- 架构、ABI、`SONAME` 或符号版本不匹配时，不能当作已解析依赖。
- 未被依赖声明或其他明确关系支持的同目录文件不自动加入。

分析组是逻辑范围，不代表所有组件一定在同一个进程中加载。

## 依赖来源

依赖解析需要明确的来源范围。第一版建议使用分析任务提供的依赖目录、sysroot 或样本目录，并记录搜索顺序。

宿主机系统目录不应在没有记录的情况下参与解析。若允许使用宿主机文件，必须记录路径、哈希和来源差异。

ELF 的搜索路径、`SONAME`、符号版本和架构信息都是解析依据。`PT_INTERP` 先作为运行时上下文保存，是否纳入依赖闭包以后再定。

## 依赖处理结果

分析组不使用统一的完整度或置信度状态。每条依赖关系直接记录处理结果：

- 找到项目内兼容文件：加入依赖闭包并递归处理。
- 项目内没有文件但属于常见 C/C++ 通用库：保留关系，使用通用库知识继续处理。
- 没有可用文件或候选无法选择：保留为待处理关系，并记录原因和候选。

这样，某个外部库没有本地文件，不会自动改变其他组件分析结论的判断。

## 典型场景

根 ELF 依赖 `libA.so`，`libA.so` 依赖 `libB.so` 时，三个组件形成同一个依赖闭包。

两个根 ELF 共享 `libcommon.so` 时，两个分析组引用同一个库组件和分析产物。

根 ELF 没有动态依赖时，它形成单成员分析组，不应被当成依赖解析失败。

同名库存在多个候选，但架构、ABI 或符号版本不匹配时，关系保持不确定，不自动猜测。

## 对静态分析引擎的输入

分析组应提供：

- 根 ELF 和依赖组件身份
- 组件文件、哈希、架构和地址上下文
- 组件关系和关系来源
- 待处理依赖及其原因
- 需要共同分析的组件范围

分析引擎分别处理各组件，再用分析组关系汇总跨组件结果。

## 当前建议

第一版先固定为：

1. 用户指定一个根 ELF。
2. 用户提供明确的依赖来源范围。
3. 系统递归建立依赖闭包。
4. 根 ELF 和依赖闭包组成一个逻辑分析组。
5. 常见库转为通用库知识引用，其他未找到的依赖保留为待处理关系。
6. 后续静态分析使用这个分析组。

## 已确认与待确认

单 ELF 只使用显式指定的依赖目录或 sysroot，不扫描父目录和宿主机系统库。rootfs 或普通目录输入时，输入目录默认作为工作根目录，系统递归发现候选并自动识别各个程序，每个程序分别建组。没有可用依赖时，常见库转为通用库知识引用，其他依赖保留为待处理关系。详见 [依赖检索与分析组构建](./03-依赖检索与分析组构建.md)。

剩余待确认：

- `PT_INTERP` 是否继续只作为上下文。
- `dlopen`、自定义加载器和运行时库名是否暂时只记录为未确认关系。
- 常见库知识引用的具体范围和提示词组织方式。

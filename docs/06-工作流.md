# Sagent 分析工作流

状态：实现稿 v1。

本文描述从 ELF 分析组到静态审计 PoC 的主流程。生产级 Agent 负责规划、按需查询和语义判断；GhidraMCP 及后续静态分析工具负责产生可复核的二进制事实。

## 总流程

```text
输入 ELF / 固件组件
  → elf.py 建立分析组
  → GhidraMCP 建立攻击面地图
  → 按需识别候选 source / sink
  → sink 驱动的参数级路径查询
  → 静态污点传播和约束收集
  → 证据整合与误报复核
  → 结构化发现项
  → 静态 PoC 和人工验证步骤
```

第一阶段的输入是 `elf.py` 输出的分析组。Agent 不自行决定依赖范围，也不把宿主机库当作事实。组件、哈希、依赖边和待处理依赖由分析组提供。

## 阶段一：攻击面和候选 source/sink

Agent 通过 GhidraMCP 先确认目标，再按需查询：

- `get_program_info`：确认当前程序和架构；
- `list_imports`、`list_exports`：获取外部边界；
- `list_functions`、`search_functions_by_name`：定位候选函数；
- `list_strings`：定位协议字段、配置项、命令和路径；
- `get_function_calls`、`get_function_xrefs`：确定调用和引用上下文；
- `decompile_function_by_address`：读取候选函数语义。

结果先分为候选 source/sink 和已确认 source/sink。出现 `system`、`popen`、`sprintf` 或网络 API 只能形成候选，不能直接形成漏洞证据。内部包装函数需要结合调用点、参数和反编译结果确认。

Agent 不应该一次读取所有函数的完整反编译结果。先用导入、字符串、调用关系和名称过滤缩小范围，再对高价值候选按需查询。

## 阶段二：sink 驱动的静态路径查询

路径查询复用 TaintSage 的 DDC/RDC 思路：从 sink 的敏感参数反向查询参数级数据依赖，再检查路径是否能追溯到外部可控 source。

需要区分：调用关系、数据依赖和可利用性。调用图不能单独证明污点传播。每条路径至少应包含 source 参数、调用点、中间参数或返回值、关键转换和 sink 敏感参数。

GhidraMCP 提供反编译、调用和交叉引用导航。参数级污点传播需要单独的静态工具或受限的 Agent 查询工具；工具必须返回每条边的来源和不支持的语义。Agent 可以决定查询哪个 sink 和补充函数，但不应独自凭自然语言完成大规模图搜索。

## 阶段三：证据整合与误报复核

证据分为 `binary_fact`、`dataflow_fact`、`reachability_fact`、`constraint_fact`、`semantic_judgment`、`negative_evidence` 和 `manual_confirmation`。每条证据需要记录组件哈希、函数或地址、工具、查询、原始产物、支持或反驳的结论和置信度。

误报复核依次检查：source 参数是否真的来自攻击者；数据是否进入 sink 敏感参数；每条跨函数传播边是否有证据；是否存在白名单、转义、边界检查或固定命令映射；路径是否可达；具体调用点参数是否可控；关键结论能否用独立 Ghidra 查询复核。

最终 findings 只分为 `confirmed` 和 `rejected`。候选、工具未知、失败和覆盖不足不进入 findings，写入 `unresolved`；`rejected` 保留排除证据，避免后续重复查询。

## 查询效率

source/sink 较多时，查询不能完全交给 Agent。静态工具负责索引、候选过滤、切片、路径搜索、去重和基础约束检查；Agent 负责候选排序、函数语义判断、下一步查询、证据整合和最终复核。

查询策略：先建立函数、导入、字符串和调用图索引；只对高风险 sink 的敏感参数反向切片；相同 sink、参数和调用上下文去重；外部库函数复用稳定分类；内部包装函数按需查询；限制路径深度、节点数、时间和 Agent 工具调用次数；保存无路径和工具不支持的语义；后续再增加函数摘要、参数映射和 sanitizer 结论缓存。

## 阶段四：PoC

静态阶段由独立的 PoC 阶段（仓库内模板 prompts/poc-stage.md 驱动 OpenCode）生成审计 PoC：触发条件、输入形态、调用路径、关键参数、证据位置和人工验证步骤。只有最终 `confirmed` finding 才能进入该阶段。默认不执行样本、不连接真实设备和网络。

PoC 生成不能提升发现置信度，必须引用已经保存的证据，并明确仍需人工确认的部分。
